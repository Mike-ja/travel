# 青岛/威海行程地图维护说明

本目录是静态行程页面。行程数据、景点坐标和地图渲染均在 `app.js` 中维护。

## 为什么地图点位容易偏

沿海景区、观景台、栈桥和夜市常有同名或相近 POI。用“景区名称”搜索时，结果可能是景区中心、公交站、停车场、咖啡店或相邻海滩；在环海路上，这些点看似只差一点，实际可能相距数公里。

字幕、攻略和截图只用于补充游玩内容、照片机位和餐饮建议，不能单独作为坐标依据。

## 新增或修改路线点的流程

1. 明确要标记的实际到达位置：主入口、停车场、观景台、拍照街口或店铺门店，不使用模糊的“景区中心”。
2. 在高德地图检索完整名称和行政区，优先打开对应的地点详情页，核对名称、地址、类别和地图位置。
3. 将坐标按高德格式写入 `app.js` 的 `coords: [经度, 纬度]`；顺序不可写成 `[纬度, 经度]`。
4. 将 `address` 写成可供导航辨认的地址。海岸景点宜包含道路、门牌或停车场名称；不要只写城市或区县。
5. 如果地点可能有多个入口，在 `note` 中说明本次使用的入口或停车位置，并将显示名称写得清楚，例如“猫头山3号观景台”而非“猫头山”。
6. 刷新 `index.html?day=day3#map`，观察路线在 10–14 级地图缩放下是否按真实海岸方向连接；核对相邻两站没有跳到另一段海岸。
7. 修改 `index.html` 中 `app.js` 的版本参数，避免浏览器继续读取旧缓存。

## 餐饮与市场参考点

Day 3 的餐饮和市场位于 `references` 数组。它们是备选点，不应代替路线中的正式停靠站。

- `name`：显示在地图标签和详情中的名称。
- `kind`：使用 `餐饮` 或 `市场`，决定地图标识样式。
- `keyword`：高德地点检索关键词，应包含店名和必要的商圈/分店信息。
- `note`：该店被推荐的原因或适合的用餐场景。

页面加载时会通过高德地点检索取得餐饮/市场的实时位置。检索结果必须同时符合名称与区域；无法可靠匹配时宁可不显示，不能用名称相近的店铺替代。成功匹配的点会显示店名标签，点击可查看详情。

截图中有一批餐饮需要集中复核时，可打开 `poi-audit.html`。该页会逐项列出高德在威海返回的候选名称、地址和坐标，先确认门店再把坐标固化回 `app.js`。

## 获取高德地点图片

当前项目的 Web 端高德 JS API Key 可通过 `AMap.PlaceSearch` 取得 POI 图片，不需要额外申请 Web 服务 Key。创建搜索实例时将 `extensions` 设为 `all`；搜索成功后，匹配 POI 的 `photos` 数组会提供图片标题、图片链接和提供方。

```js
const placeSearch = new AMap.PlaceSearch({
  city: "青岛",
  citylimit: true,
  pageSize: 5,
  extensions: "all",
});

placeSearch.search("栈桥景区", (status, result) => {
  const poi = status === "complete"
    ? result?.poiList?.pois?.find((item) => item.name?.includes("栈桥"))
    : null;
  const photos = poi?.photos || [];
  // photos[0] 形如 { title, url, provider }
});
```

页面不会在访问时检索图片。已核对的结果写在 `app.js` 顶部的 `STOP_PHOTOS` 中，按 `day:stopIndex` 对应到行程停靠点，每个地点最多两张，并直接引用高德返回的图片 URL。没有可靠图片的地点保持无图；入住地点和民宿不放图片。

新增或更新图片时，先在维护环境中用上面的 `PlaceSearch` 查询，核对 POI 名称、地址和坐标。优先选同名 POI；同名无图时，可采用附近入口、同名街区或相邻景点的图片作为代表，但 `sourceName` 必须写入实际 POI 名称，且 `nearby` 设为 `true`，让页面明确标注来源。确认后将最多两条 `{ url, sourceName, nearby }` 写入 `STOP_PHOTOS`，不要让正式页面在运行时搜索。

高德的 Web 服务 POI 搜索接口也能返回 `photos`，但必须使用单独申请的“Web 服务”类型 Key，不能复用本项目的 JS API Key。

## 提交前检查

- 路线每个点都有准确的名称、地址、`[经度, 纬度]` 坐标和停留说明。
- 跨城转场不要参与本地景区的自动聚焦，避免地图缩放得过远。
- 景点与餐饮参考点的标签不遮挡关键路线；必要时缩短显示名称，但保留完整 `name`。
- 在浏览器实际打开 Day 1–Day 5，切换日期后确认地图、地点列表、路线顺序和详情弹窗一致。
- 运行 `node --check qingdao/app.js` 与 `git diff --check`。
